# daily-stress-check

## 入力

- interview-summary: なし（ユーザー依頼: 「日記を書いたらその日のストレスチェックをして、メンタル診断をするようなskillを作って」）

## 目的整理

- 背景: 日記を書いた後に、その日の心身の負荷を短時間で振り返りたい。
- 課題: 自由記述の日記から、感情・負荷要因・回復要因を一貫して整理しにくい。
- 期待効果: 毎回、読みやすいセルフチェックと次の一歩を得られる。
- 制約: 医療診断、病名の断定、治療指示はしない。危機サインは緊急支援と身近な人・専門家への相談を優先して案内する。
- 未確定事項: 長期の記録保存・数値トレンド機能は今回扱わない。

## 曖昧さの整理

- 理解したこと: 日記本文を入力に、その日のストレス状態を振り返る再利用可能な Codex skill を作る。
- 確認が必要な点: なし。今回の PoC は単一の日記へのチャット回答に限定する。
- TBD で進める点: 将来の複数日比較、外部サービス連携、地域別相談窓口。

## 解決手段の選定

- 選定した手段: Codex Skills
- 選定理由: 日記テキストを受け取り、一定の安全境界と出力形式で返す反復作業であり、Web UI や外部連携は不要。
- 採らなかった案: Web App は入力画面・保存を必要としないため過剰。GPTs は Codex 内で使う再利用スキルという依頼に合わない。
- トレードオフ: 長期記録の可視化や医療的評価は提供しない。

## 成立条件

- 想定ユーザー: 日記を通じて、その日のストレス傾向と自分にできる次の一歩を振り返りたい人。
- PoC 成立条件: 日記から根拠つきの低・中・高のストレス目安、感情・負荷・回復要因、低負荷の提案、安全案内を表示できる。
- TBD: 相談先の地域・言語の個別最適化。

## 中核要件

- REQ-01: Must — 日記本文から、ストレス目安と根拠、感情、負荷要因、回復要因を日本語で整理する。
- REQ-02: Must — 医療診断・病名断定・治療指示を避け、セルフチェックであることを明示する。
- REQ-03: Must — 自傷・自殺念慮・切迫した危険が示される場合、通常の分析より安全確認と緊急支援の案内を優先する。
- REQ-04: Should — 日記が短い・情報不足の場合、断定せず不足を示して負担の少ない追記質問を一つだけ返す。
