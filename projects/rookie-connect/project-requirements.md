# Rookie Connect

## 入力

- interview-summary: `interview-summary.md`

## 目的整理

- 背景: 新入社員の配属後に、横のつながりを作る場が必要。
- 課題: 気軽な発信、質問、共感を一か所で行えない。
- 期待効果: 新人が近況や困りごとを共有し、会話を始めやすくする。
- 制約: PoC はローカルで動くブラウザアプリ。実際の社員データ、認証、外部送信は扱わない。
- 未確定事項: 社内規程、モデレーション、正式な認証方式、永続化方式は TBD。

## 曖昧さの整理

- 理解したこと: X に近いタイムライン中心の社内 SNS が必要。
- 確認が必要な点: 最重要機能、初回の操作導線、最低限必要な画面は、下記の PoC 仮説でよいか。
- TBD で進める点: アプリ名、配色の細部、実運用向けの管理機能。

## 解決手段の選定

- 選定した手段: Web App
- 選定理由: 投稿・閲覧・反応といった対話操作を画面上で検証でき、最小構成をローカルで素早く試せる。
- 採らなかった案: GPTs / Codex Skills は会話用ではなく、共有タイムラインの検証に適さない。Workflow は実際の利用体験を示せない。
- トレードオフ: PoC ではデモデータとブラウザ内状態を使うため、複数人による実時間利用やログインは検証しない。

## 成立条件

- 想定ユーザー: 配属直後の新入社員。
- PoC として何ができれば十分か: タイムラインを見て、短文を投稿し、投稿にリアクションまたは返信して、会話のきっかけを作れる。
- 今回作る範囲: ホームタイムライン、投稿作成、いいね、返信、話題タグ、プロフィール表示、モバイル対応。
- 今回作らない範囲: 実認証、実ユーザー招待、サーバー保存、DM、画像添付、通知、通報・管理、外部公開。
- TBD: 正式な社内ルールと、本番で必要な権限・モデレーション要件。

## 中核要件

- REQ-01: 初めて開いたユーザーが、新人向けの投稿タイムラインを確認できる。
- REQ-02: ユーザーが 280 文字以内の投稿を作成し、直ちにタイムラインへ表示できる。
- REQ-03: ユーザーが投稿へ「いいね」または返信を行い、状態変化を確認できる。
- REQ-04: 入力が空、または文字数上限を超える場合は投稿を作成しない。
