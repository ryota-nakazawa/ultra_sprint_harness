# 評価サブエージェント未実施に関する記録

## 事象

新人向け社内 SNS プロトタイプ `rookie-connect` の作成後、本来は実装担当とは別コンテキストの評価サブエージェントによる判定を行うべきだったが、評価サブエージェントを起動しないまま、実装担当自身の確認結果を `Pass` 相当として扱ってしまった。

そのため、`projects/rookie-connect/evaluation-runs/{run-id}/` 配下に保存されるべき以下の評価証跡は存在しない。

- `receipt.json`
- `evaluator-input.md`
- `evaluator-result.md`

結果として、現在残っている確認結果は「実装担当による静的確認・簡易動作確認」であり、「独立した LLM 評価エージェントによる評価」とはみなせない。

## 直接原因

直接原因は、実装後の確認を「技術的な自己確認」として扱うべきところを、ハーネス上の評価結果に近いものとして記録してしまったことにある。

具体的には、HTML / CSS / JavaScript の実装確認、`node --check`、ローカル配信確認、コード上の機能確認を行った時点で、受け入れ条件や eval case の一部を満たしたと判断した。しかし、この判断は実装担当自身の観察であり、AGENTS.md に定義されている「実装担当とは別コンテキストの評価エージェントによる LLM 判定」ではなかった。

## 構造的原因

構造的には、実装完了後に「この判定は自己確認か、独立評価か」を明示的に分岐するゲートを置かなかったことが原因である。

AGENTS.md では、LLM 判定を使う場合に次の条件が定義されている。

- 実装担当とは別コンテキストの評価エージェントを使う
- 評価エージェントには限定された成果物と評価資料だけを渡す
- 評価ごとに `evaluation-runs/{run-id}/` を作成する
- `receipt.json`、`evaluator-input.md`、`evaluator-result.md` を保存する

今回の進行では、実装後の確認フェーズでこの条件をチェックせず、自己確認の延長として `Pass` 判断を先に置いてしまった。つまり、サブエージェントの存在を意図的に否定したというより、評価フェーズへの遷移時に「独立評価が必要な局面である」という認識を落とした。

## 影響

この漏れにより、以下の影響がある。

- 評価結果の独立性が担保されていない
- 受け入れ条件や eval case の `Pass` 表記を、正式な LLM 評価結果として扱えない
- UI の使いやすさ、投稿・返信・いいねなどの主要操作が、第三者視点で再現確認されていない
- ハーネスが要求する評価証跡が欠落しているため、後続の改善ループや比較に使えるログとして不完全である

## 再発防止

再発防止として、今後は実装後の評価フェーズに入る前に、次のゲートを必須にする。

1. 判定種別を明記する
   - `実装担当による自己確認`
   - `人間レビュー待ち`
   - `独立 LLM 評価`

2. `独立 LLM 評価` を使う場合は、評価結果を書く前に必ず評価サブエージェントを起動する。

3. 評価サブエージェント起動時点で `evaluation-runs/{run-id}/receipt.json` を作成し、agent ID と `fresh_context` を記録する。

4. 評価依頼内容を `evaluator-input.md` に保存し、評価サブエージェントの返答全文を `evaluator-result.md` に保存する。

5. `Pass / Fix / Needs Review` は、上記の証跡がそろった後にだけ正式な LLM 評価結果として記録する。

6. 証跡がない場合は、既存の確認結果を `実装担当による参考確認` と明記し、独立評価済みとは書かない。

## 現時点の扱い

現時点では、`rookie-connect` は実装済みのローカルプロトタイプであり、実装担当による簡易確認は済んでいる。一方で、独立した評価サブエージェントによる評価は未実施である。

そのため、現在の評価ステータスは次のように扱うのが正しい。

- 実装: 完了
- 自己確認: 一部完了
- 独立 LLM 評価: 未実施
- ユーザー確認: 未完了

## 是正実施（2026-07-14）

この記録を受け、実装担当の自己確認と独立評価を分ける `evaluation-status.md` と、評価証跡を確認する `tools/check_evaluation_evidence.py` を追加した。

独立 LLM 評価を `fresh_context` で実施し、評価証跡は `evaluation-runs/20260714T123440Z-iteration-00/` に保存した。結果は `Needs Review` であり、初見利用者による操作発見性の確認と、ブラウザ実行時のコンソール確認が未完了である。

この結果は、自己確認の `Pass` ではなく独立評価の正式結果として `acceptance-criteria.md`、`eval-cases.md`、`sprint-metrics.md` に反映済みである。
