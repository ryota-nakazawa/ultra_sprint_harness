LLM 判定を使う場合は、実装担当とは別コンテキストの評価エージェントに、成果物、実行手順、`acceptance-criteria.md`、このファイルだけを渡す。
実装中の会話ログや背景説明は渡さない。
自動修正は最大 2 回まで。3 回目の実装・評価には入らない。

## 1. 評価観点

| 観点 | 見ること |
|---|---|
| 業務成功 | カウンターの基本操作が成立するか |
| 誤実行 | Reset などの操作で誤った状態が残らないか |
| 再現性 | 操作結果が UI 表示に一貫して反映されるか |

| ID | 種別 | 評価観点 | テストレベル | 入力 | 期待される振る舞い | NG 例 | 採点方法 | 結果 | メモ |
|---|---|---|---|---|---|---|---|---|---|
| E-01 | 代表 | 業務成功 | 構成・単体 / 業務シナリオ | `increment` ボタンを押す | `count` が 1 増え、ステータスに増加が表示される | ボタンがない、値が増えない | 評価エージェント | Pass | iteration 0 から Pass |

## 2.5 評価エージェントへの入力

- 成果物: `index.html`, `styles.css`, `app.js`
- 実行手順: ブラウザで `index.html` を開く。ファイル検査では HTML の ID と JS のイベント定義を確認する。
- `acceptance-criteria.md`
- `eval-cases.md`

渡さないもの:

- 実装中の会話ログ
- 実装者の判断理由や言い訳
- 未完成箇所の補足説明

## 2.6 自動評価ループの停止条件

| 条件 | 今回の結果 |
|---|---|
| すべて `Pass` になった | Yes |
| `Needs Review` が 1 件以上出た | No |
| 自動修正が 2 回に達した | No |
| 同じ ID が 2 回連続で `Fix` になった | No |
| 修正にスコープ変更や評価基準変更が必要になった | No |
