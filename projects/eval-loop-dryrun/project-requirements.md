# Eval Loop Dry Run

## 入力

- 目的: 自動評価ループが `Fix` を検出し、実装修正後に `Pass` へ進む様子を確認する。

## 目的整理

- 背景: ループエンジニアリングと evals の運用が、ドキュメント上だけでなく記録としてどう残るかを見たい。
- 課題: 不合格時に、どのように評価エージェントが `Fix` を出し、実装が戻り、再評価されるかが見えにくい。
- 期待効果: 小さな成果物で、自動評価ループのログ形式を確認できる。
- 制約: 静的 HTML / CSS / JavaScript の最小サンプルにする。外部 API、ビルド、ブラウザ自動操作は使わない。
- 未確定事項: 実運用での評価エージェント起動方法は TBD。

## 解決手段の選定

- 選定した手段: Web App
- 選定理由: 1画面のカウンターなら、意図的な未実装と修正を短時間で確認できる。
- 採らなかった案: GPTs / Codex Skills は UI の壊れた導線を見せるサンプルとしては分かりにくい。
- トレードオフ: 実際のブラウザ操作ではなく、ファイル検査ベースの評価に留める。

## 成立条件

- 想定ユーザー: ハーネス設計者
- PoC 成立条件:
  - カウンターの現在値が表示される
  - Increment ボタンで値が 1 増える
  - Reset ボタンで値が 0 に戻る
  - 操作結果がステータステキストに表示される
- TBD: 将来は Playwright などで実操作評価するか。

## 中核要件

- REQ-01: カウンターの現在値を表示し、Increment で 1 増やせる
- REQ-02: Reset で値を 0 に戻し、結果を画面に表示できる
