# 問い合わせ一次対応トリアージ

## 入力

- interview-summary: `interview-summary.md`

## 目的整理

- 背景: 中堅メーカー A 社の CS 部門では、月間約 1,200 件の問い合わせを担当者が目視で緊急度とカテゴリに振り分けている。
- 課題: 朝の一次振り分けが属人化し、ベテラン不在時に判断品質が落ちる。緊急案件の見落としも発生している。
- 期待効果: 一次振り分け時間を半減し、緊急案件の見落としを減らし、AI 分類が現場感覚と合うかを判断できる状態にする。
- 制約: 実データは使わずモックデータ 30〜50 件でデモする。認証・保存・メール連携は扱わない。デモ時間は 15 分。
- 未確定事項: 必要精度の基準、「使いやすい」の具体条件、本格導入時の既存システム連携。

## 曖昧さの整理

- 理解したこと: 経営判断用に、AI 分類の体験と分類結果の修正操作を見せる Web App プロトタイプが必要。
- 確認が必要な点: 本番精度の合格ラインは未定。ただし今回の PoC では、分類ロジックの厳密な精度より、判断・修正・全体把握の体験を優先する。
- `TBD` で進める点: 実データ連携、認証、履歴保存、分類モデルの本格評価。

## 解決手段の選定

- 選定した手段: Web App
- 選定理由: CS 部長と経営企画に 15 分で「動くもの」を見せ、問い合わせ一覧、分類結果、修正、集計をその場で体験してもらう必要があるため。
- 採らなかった案: GPTs は画面操作と CSV 取り込み体験を見せにくい。Codex Skills は現場担当者向けの操作画面にならない。Workflow / ハーネス設計は今回の成果物とズレる。
- トレードオフ: AI 分類はモックのルールベース判定に留め、分類モデルの精度評価は本格導入検討時の別テーマにする。

## 成立条件

- 想定ユーザー: CS 部長、経営企画、CS 担当者
- PoC 成立条件:
  - CSV またはサンプルデータから 30 件以上の問い合わせを一覧表示できる
  - 各問い合わせに緊急度（高・中・低）とカテゴリ（製品不具合／使い方／請求／その他）が付く
  - 件数の全体感をダッシュボードで確認できる
  - 誤分類を人が画面上で修正できる
  - デモ中に、AI 化の投資判断に必要な論点を説明できる
- TBD: 本番精度の数値基準、既存システム連携方式

## Web App 要件

【アプリ名】CS Triage Desk
【入力】`interview-summary.md` とモック問い合わせデータ
【一言で】問い合わせの一次分類を AI 風に自動付与し、現場が確認・修正できるプロトタイプ
【コア機能】
- サンプル 40 件の読み込み
- 緊急度・カテゴリの自動分類
- 緊急度、カテゴリ、未確認/確認済みの集計
- 行ごとの緊急度・カテゴリの修正
- CSV ファイルの取り込み
【画面構成】
- 1画面構成: 上部に集計、左にフィルタ、中央に問い合わせ一覧、右に選択行の詳細と修正
【API / バックエンド】
- 不要。ブラウザ内で完結する。
【デザイン方針】
- 業務利用向けの静かな画面。白背景、青系アクセント、表の読みやすさを優先する。
【UIイメージ生成】
- 不要。要件から業務画面像が明確なため、直接実装する。

## Frontend Direction

- visual thesis: 白基調の業務卓に、緊急度だけが視線を引く青と赤の控えめな状態表示を置く。
- content plan: 集計、フィルタ、問い合わせ一覧、選択詳細、修正操作を1画面に集約する。
- interaction thesis: 行選択で詳細が滑らかに切り替わり、分類修正は即時に集計へ反映される。CSV 取り込み時は件数と分類が即座に更新される。
