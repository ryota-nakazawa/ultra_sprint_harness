# cosmetics-ec

## 入力

- interview-summary: `interview-summary.md`

## 目的整理

- 背景: 化粧品をオンラインで販売できる EC サイトのプロトタイプが必要。
- 課題: 商品の魅力と購入導線を同時に確認できる画面がない。
- 期待効果: 商品閲覧から注文完了までをブラウザ上で体験し、販売サイトとしての方向性を判断できる。
- 制約: 実決済、認証、在庫連携、配送 API は PoC 範囲外。商品情報は仮データ。
- 未確定事項: 正式ブランド、商品ラインアップ、法務レビュー、決済会社、配送条件。

## 曖昧さの整理

- 理解したこと: 最小の成果物は、化粧品販売の主要導線が触れる Web App。
- 確認が必要な点: 実ブランド適用、実商品画像、決済導入、法務表記の最終確認。
- `TBD` で進める点: ブランド名、商品説明、価格、送料条件、運用ポリシー。

## 解決手段の選定

- 選定した手段: Web App
- 選定理由: ユーザーが「ECサイトを構築」と依頼しており、ブラウザで商品選択から注文完了までの UI を確認することが最小。
- 採らなかった案: GPTs は販売画面を提供できない。Codex Skills は再利用ワークフロー向け。Workflow / ハーネス設計は成果物がプロセス定義になるため今回の目的と異なる。
- トレードオフ: 静的 PoC なので実決済や在庫更新は確認できないが、購入導線と画面設計は短時間で検証できる。

## 成立条件

- 想定ユーザー: 化粧品販売事業者、EC 担当者、購入者役のレビュー参加者。
- PoC 成立条件:
  - 商品一覧から商品を選び、カートに追加できる。
  - カート内の数量変更と削除ができ、合計金額が更新される。
  - 購入者情報を入力して注文確認へ進める。
  - 必須項目が不足している場合は注文完了に進まずエラーが分かる。
  - 注文完了画面で注文番号と合計金額が確認できる。
- TBD: 実決済、会員登録、在庫数、配送日時指定、特定商取引法表記の正式文面。

## 中核要件

- REQ-01: 商品の発見と比較ができる。
- REQ-02: カート操作と金額更新ができる。
- REQ-03: チェックアウトの入力検証ができる。
- REQ-04: 注文完了の結果を確認できる。
