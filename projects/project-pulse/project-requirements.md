# Project Pulse

## 入力

- interview-summary: `interview-summary.md`

## 目的整理

- 背景: チームの進捗とリスクを別々に追う負担を減らしたい。
- 課題: タスクの遅延や対応が必要なリスクを、担当者が早期に一覧で判断しにくい。
- 期待効果: プロジェクト責任者がダッシュボードだけで優先対応を判断できる。
- 制約: ログインなし、ローカルブラウザ保存のみの単一ユーザーPoC。
- 未確定事項: 将来の共有・権限・通知の運用ルールはTBD。

## 曖昧さの整理

- 理解したこと: タスクとリスクを一つのワークスペースで扱い、最初にダッシュボードを表示する。
- 確認が必要な点: 本番時のユーザー権限とデータ共有方式。
- TBDで進める点: プロジェクト名、メンバー構成、外部連携先。

## 解決手段の選定

- 選定した手段: Web App（HTML / CSS / JavaScript、localStorage）。
- 選定理由: ダッシュボードで一覧・追加・更新を直接操作することがPoCの中心であり、最小構成で体験検証できる。
- 採らなかった案: Codex Skills/GPTsは対話支援が中心で画面操作の検証に不向き。バックエンドは共有・認証が対象外のため不要。
- トレードオフ: 同一ブラウザでのみデータを保持し、複数人共有は検証しない。

## 成立条件

- 想定ユーザー: 小規模チームのプロジェクト責任者、リーダー。
- PoC成立条件: タスクとリスクを登録・更新し、期限超過・高リスクをダッシュボードで確認して優先対応を判断できる。
- TBD: 実運用で使うリスク評価基準と通知条件。

## 中核要件

- REQ-01: 利用者はタスクを作成し、担当者、期限、状態を更新できる。
- REQ-02: 利用者はリスクを作成し、重要度、担当者、対応状況を更新できる。
- REQ-03: ダッシュボードは期限超過のタスクと高リスクの未解決項目を優先表示する。
- REQ-04: タスクとリスクの変更はページ再読み込み後も同一ブラウザで保持される。
